# BSCH Clinics

نظام عربي RTL لإدارة حجز وانتظار العيادات، مبني كتطبيق Full-Stack قابل للتشغيل والتعديل.

## ما تم تنفيذه فعلياً

- حجز خارجي بدون تسجيل: الاسم، الهاتف، العيادة، التاريخ والموعد.
- حالة Pending للحجز الخارجي ثم تأكيده من موظف الحجز وإصدار رقم دخول متسلسل لكل عيادة/يوم.
- متابعة الحجز بالهاتف ورقم الحجز.
- حجز داخلي عبر API لموظف الحجز.
- حسابات وصلاحيات Server-Side للأدوار: موظف حجز، طبيب، تمريض.
- Queue فعلي: نداء، داخل الكشف، التالي، تخطي، إعادة للانتظار، وإكمال.
- تحويل الحجز إلى عيادة أخرى مع إنشاء Queue جديد وحفظ سجل التحويل.
- شاشة انتظار عامة تعرض الحالي والتالي.
- سجل عمليات AuditLogs وإشعارات وسجل أحداث الدور.
- قاعدة SQLite بعلاقات حقيقية تشمل: Users, Clinics, ClinicSchedules, Bookings, QueueEntries, QueueEvents, Transfers, Notifications, AuditLogs.
- طباعة كشف A4 من لوحة التحكم عبر CSS للطباعة.

## التشغيل المحلي

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python app.py
# افتح http://127.0.0.1:4173
```

يتم إنشاء `bsch_clinics.sqlite3` تلقائياً مع الجداول والعيادات والحسابات الأولية.

## الحسابات الأولية

| الدور | المستخدم | كلمة المرور |
|---|---|---|
| موظف الحجز | `bsch` | `bsch` |
| الطبيب | `bschdr` | `bschdr` |
| التمريض | `bschnurse` | `bschnurse` |

## الاختبار السريع

```bash
python -m py_compile app.py
python app.py
```

ثم جرّب من الواجهة: حجز خارجي، تسجيل الدخول بموظف الحجز، تأكيد الحجز، ثم تسجيل الدخول بالطبيب أو التمريض وتنفيذ إجراءات الدور.

## البنية

- `app.py`: الخادم، قاعدة البيانات، الصلاحيات، API، وقواعد العمل.
- `templates/index.html`: shell الواجهة.
- `static/app.js`: واجهة RTL وتدفقات الحجز والمتابعة ولوحة التحكم وشاشة الانتظار.
- `static/app.css`: التصميم المتجاوب والطباعة.
- `bsch_clinics.sqlite3`: قاعدة التشغيل المحلية، مستبعدة من Git لأنها بيانات تشغيلية.
- `assets/`: الصور والملفات البصرية.

> هذه النسخة تعالج الفجوة التي كانت موجودة في المستودع السابق: الموقع السابق كان Build مجمعاً فقط، أما النسخة الحالية فتحتوي على كود الخادم والواجهة وقاعدة البيانات القابلة للتعديل.
